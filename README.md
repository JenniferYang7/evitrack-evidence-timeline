# EviTrack｜投资事件情报与证据时间线

> 同花顺 AI 产品经理笔试 · 第 3 题 · **具备运行代码的 Web MVP**（Streamlit；上线后需再次验收）

## 1. 目标用户与产品价值

目标用户：研究某项政策或投资事件、需要核对不同来源和版本的投资研究者与普通投资者。

问题：同一事件在政府公告、媒体报道、分析观点、未经证实信息中反复出现；若简单按新闻标题汇总，容易混淆**发布时间、实际发生时间、事实、推断和修订版本**。

核心思路：**证据先于结论、时间先于叙述、状态由确定性规则计算，AI 不得篡改已核验事实。**

本版以 **2025年5月央行降准** 作为真实历史样例，披露时间跨度2025年5月7日至15日。官方披露明确降准0.5个百分点、预计释放长期流动性约1万亿元、5月15日落地。这里的“预计”不被写成“实际到账”，相邻的7天逆回购利率下调也不被错误合并为同一指标。

## 2. 核心交互主链路

1. **打开事件总览**：看到状态、可信资料数量、冲突数量、原始链接，以及标的影响证据边界。
2. **调整左栏“证据回放截至日期”**：设为 `2025-05-06` → `证据不足`；设为 `2025-05-08` → `已宣布，待确认落地`；设为 `2025-05-15` → `已实施（有公开证据）`。
3. **查看证据时间线**：每张卡展示原始来源、事实/观点、披露/发生/采集/更新四种时间、引用依据、版本及链接。
4. **开启“合成冲突测试”**：一条明确标注为虚构的“降准1个百分点”材料被识别为冲突，不能覆盖0.5个百分点的可信依据。它**不是真实网络传言**。
5. **新增证据**：粘贴标题、媒体、披露和发生时间、正文；规则提取主要降准数值与可能生效日，检查事件关联，按来源规范化URL和指纹去重；同URL不同正文创建版本。
6. **使用 AI 分拣**：配置服务器端 API Key 后，LLM 对粘贴文本做初步事实/观点/推测/传闻分类、提要和不确定性提示；结果须人工核对，**不修改确定性事件状态**。
7. **导出原始证据**：下载 JSON，保留关键来源/时点/字段及是否人工核验标记。

## 3. 本地启动

要求 Python 3.10+。

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

通常会在本机打开 `http://localhost:8501`。

## 4. 发布成可访问网站

**笔试要求必须是外网可访问 URL。压缩包和 `localhost` 地址本身不算完成。**

1. 在 GitHub 建立一个公开仓库，例如 `evitrack-timeline`；上传本目录代码，**不要上传任何真实密钥**。
2. 进入 [Streamlit Community Cloud](https://share.streamlit.io/)，使用 GitHub 登录并点击新建 App。
3. 选择仓库、分支 `main`、入口文件 `app.py`，点击 Deploy。
4. 部署后得到 `https://<your-app>.streamlit.app/` 等公开 URL；**必须用浏览器无痕窗口验证能加载和交互**。
5. 按要求提交：部署 URL、GitHub 仓库 URL、README、本项目 `AI_USAGE.md`、`TEST_PLAN.md`（以及选做演示视频）。

此项目的生成环境没有自动创建公开的 GitHub 仓库或公开网站，因此压缩包**不包含真实线上部署链接**。需要按步骤自行完成发布。

### 可选的大模型配置

在 **Streamlit Cloud → App settings → Secrets** 添加：

```toml
OPENAI_API_KEY = "YOUR_PRIVATE_KEY"
OPENAI_MODEL = "gpt-4o-mini"
```

或在服务器设置同名环境变量。**不要把密钥提交至 GitHub**。

- 不设置时，“AI 分拣助手”会诚实提示未配置；其他证据和时间线核心功能照常运行。
- 配置后才会调用 OpenAI API；用户输入文本会发送至相关服务，应避免上传个人隐私、受限研报全文或非公开材料。
- 本 MVP 不连接扶摇/iFinD：题目写明金融数据优先使用这些渠道，但未强制必须调用；此原型采取公开政府与媒体资料作为可核验来源；需遵守数据访问权和第三方网站条款。示例来源全部为可核查的公开网页。

## 5. 技术架构与 AI 角色边界

| 层 | 实现 | 不能做什么 |
|---|---|---|
| 展示与交互 | `app.py` (Streamlit) | 不把未披露资料说成过去已知 |
| 状态和冲突 | `engine.py` (确定性规则) | 不让AI自由决定公告“落地”或数据的可信度 |
| 真实样例 | `sample_evidence.json` | 不把政策“预计流动性”说成实际到账 |
| AI解释层 | `ai_assist.py` (可选 LLM) | 不凭空填数字、不自动升格用户材料为事实 |
| 质量控制 | `tests/test_engine.py` | 无数据时不输出“正常/已证实”的状态 |

**可信度是产品设计规则，不是数学意义的客观事实概率。**

- 官方原始披露 5
- 官方权威转载 4
- 专业媒体 3
- 分析观点 2
- 待核验材料 1
- 未经证实传闻 0

输入来源默认处于**待核验**，哪怕材料文字自称“官方”。需要进一步开发后台人工复核工作流才能升级可信状态。

## 6. 指标、来源与四种时间

- `rrr_cut_pp`: 降准数值，单位**百分点**，不与 `%` 混淆。
- `expected_liquidity_cny_trillion`: 预计长期流动性规模，单位**万亿元人民币**，不是实际放贷或实际到账值。
- `published_at`: 材料公开披露日期，决定在历史回放中何时可见。
- `occurred_at`: 事件实际发生或所述事件日期（可能和披露日期不同）。
- `collected_at`: 系统记录采集日期。
- `updated_at`: 来源新版本/系统更新日期；无更新时不得擅自生成。

详细原始URL及证据映射见 `SOURCE_AUDIT.md`。

## 7. 当前做到了什么 / 未做什么

**已完成**：真实公开资料的样例、事件状态变化、披露时点回放、分类和来源链接、来源冲突提示、版本追踪、事件归属检查、上传文字材料、JSON导出、单元测试、可选LLM辅助分类。

**未完成且不能假装完成**：真实线上网站的发布（等待账号授权）、独立后台数据库和用户体系、实时自动抓取/监控、真实用户提醒推送、实际行情数据/券商权限数据对接、自动核验新增来源、个股因果归因、生产环境压力/安全审计、真实模型API在线调用（取决于是否配置密钥）。

本 MVP 采取**单个可深挖事件**的产品取舍，优先证明“同一事件多源版本的可靠理解”，未来可将事件聚类扩展为多事件索引。
